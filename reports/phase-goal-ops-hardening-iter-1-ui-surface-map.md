## Backend-Only Changes (No UI Impact)

- `apps/backend/app/api/data.py` — docstring/comment updates only (describing the removed range cap and the still-unchanged inverted-range rejection); no route, request/response schema, or status-code behavior changed in this file itself — the actual behavior changes live in `data_manager.py` and `config.py`, already captured in the surface map above. No independent UI surface.
- `apps/backend/scripts/build_qa_fixture_db.py` — internal QA tooling script (not part of the running product); updated only to stop reading the now-deleted `max_range_days` config field so the script itself doesn't crash on next use. No UI surface.
- Backend test suite changes — `apps/backend/tests/test_data_manager.py`, `test_api_data.py`, `test_config.py`, `test_config_engine.py`, `test_themes.py`, `test_sectors.py`, `test_indexes.py`, `test_data_manager_backfill_committed_session.py`, `test_data_manager_backfill_parallel.py` — pin the new no-cap / new-breakdown contract at the test level. No UI surface (tests are not shipped to users).
- `apps/backend/app/config.py` (`DataManagerCfg`/`ImportChunkingCfg` schema) and `config.yaml` (`max_range_days` line removed) — the underlying configuration/validation mechanism behind the "form now accepts >370-day ranges" row above. Not a standalone UI surface — folded into that row's rationale rather than listed twice.
