## Backend-Only Changes (No UI Impact)

- `apps/backend/app/engine/data_manager.py::_run_job`'s new `elif` branch + the new `_coverage_snapshot_is_current` helper — the internal decision logic for *when* to call the existing `refresh_coverage_snapshot`. Its only user-facing effect is fully captured in the first two surface-map rows above; the branch itself has no independent UI surface.
- `apps/backend/app/engine/data_manager.py::_upsert_coverage_snapshot`'s widened bulk `DELETE ... WHERE dataset_version != :current` (B2) — pure internal storage housekeeping that reclaims orphaned `coverage_snapshot` rows across every as-of date, not just the one being written. No UI element displays this table's row count or a "cleanup ran" indicator anywhere; verifiable only by querying the database directly.
- `apps/backend/tests/test_data_manager.py` — 6 new unit tests (`test_fetch_that_lands_new_bar_refreshes_coverage_snapshot`, `test_zero_work_fetch_skips_coverage_recompute_and_row_write`, `test_fully_failed_fetch_writes_no_coverage_snapshot`, `test_stale_dataset_version_rows_pruned_via_one_bulk_delete`, `test_fetch_coverage_refresh_makes_no_network_call`, `test_expand_that_lands_new_bar_refreshes_coverage_snapshot`) — pin the above contracts at the test level. Tests are not shipped to users; no UI surface.
- `reports/perf-budgets.md` — new **Item L**, recording the TC-8/TC-9 live health/memory measurement numbers (1,725 health polls, VmPeak 40.9% under the 6144 MB cap, etc.) — an internal engineering report, not part of the running product. No UI surface (mirrors how iter-2's Items J/K were treated).
- `docs/handoffs/goal-ops-hardening-iter-3-dev.md` — developer documentation of the B1/B2 fix and the live measurement. No UI surface.
- **The "expand" job kind's half of the B1/B2 fix** (`test_expand_that_lands_new_bar_refreshes_coverage_snapshot`, TC-3/TC-6) — implemented and unit-tested identically to the fetch path, but there is no button, form, or control anywhere in `apps/frontend` that submits a `kind="expand"` job (confirmed by a full-repo search: the only frontend matches for the string "expand" are unrelated table-row-expand chevron `aria-label`s on `/themes`, `/sectors`, and the `/research` lab, plus the `DataJobKind` TypeScript type declaration itself). This half of the fix is reachable only via a direct API call, not via any click path — no UI surface to test it against.
