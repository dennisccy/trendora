# Goal Iteration 27 — Implementation Summary

**Phase:** goal-i_can_see_the_wealthy_future_forever_with_my_loved_ones-iter-27
**Date:** 2026-06-17
**Written by:** developer

---

## Features Implemented

- **Rebuild snapshots for the current universe (J-85)**: A new operator action on the Data Manager
  (`/data`) page that, behind a confirmation dialog, clears every saved daily snapshot and recomputes
  the whole set from scratch over the current list of scanned stocks. This is the step that makes newly
  added stocks (e.g. after a universe expansion) appear on every page. The committed price history is
  never deleted — only the derived snapshots are regenerated. Progress shows live in the existing job
  card.
- **"Members absent from the latest snapshot" diagnostic (J-85)**: A read-only banner on `/data` that
  states how many of the scanned-universe stocks are missing from the most recent snapshot ("N members
  absent — rebuild to include them"). When none are missing, it shows a calm "all members present" note
  instead of a warning banner.
- **Max-drawdown paired with every forward return (J-86)**: For every stock, theme, and sector, beside
  each existing 1/5/10/20/60-day forward-return figure there is now a paired "max drawdown" figure — the
  worst peak-to-trough drop over that same window (always zero or negative, or "NA" when the window
  isn't complete yet). It appears on the Stocks leaderboard, the Stock Detail page, the Themes
  leaderboard, the Sectors leaderboard, the Backtest evidence tables, and the Research tables.

---

## Changed Behavior

- **Forward-return tables on Stocks / Themes / Sectors**: Previously showed five forward-return columns.
  Now each page also shows five paired max-drawdown columns to the right of them, each sortable and
  colour-graded (a worse drawdown reads redder; not-yet-available shows "NA").
- **Stock Detail forward-return panel**: Previously showed only the realized return per horizon. Now each
  horizon card also shows its paired max drawdown underneath the return.
- **Backtest evidence + Research tables**: Previously reported mean forward returns (and MAE/MFE on
  Research). Now they also report an aggregate "mean max drawdown" beside the return statistics, with the
  same sample-size / low-sample / NA honesty rules.
- **The forward-returns data served by the API**: Each forward-return entry now carries an extra
  `max_drawdown` value. This is purely additive — existing fields are byte-for-byte unchanged.

## Config and Environment Changes

- **No new environment variables or config keys.** The max-drawdown horizons come from the existing
  `config.walk_forward.horizons` (no hardcoded list). The rebuild reads the committed seed offline.
- **Database column added (auto-migrated, no manual step):** a new nullable `max_drawdown` column on the
  existing `forward_returns` table. A fresh database gets it automatically; an existing live database
  gains it in place on next boot via the project's additive-column mechanism (no Alembic). Existing rows
  read "NA" until the next confirm-gated rebuild repopulates the forward returns.

---

## Known Limitations

- **The rebuild is a heavy, full-calendar operation.** Over the full committed seed it recomputes a
  snapshot for every covered trading day and can take several minutes. It is deliberately operator-
  triggered and confirm-gated; it never runs automatically. Progress is shown live and counters never
  exceed their totals.
- **Existing forward-return rows show "NA" max drawdown until a rebuild.** Because max drawdown is a new
  stored value, snapshots that were computed before this iteration carry no max-drawdown until they are
  regenerated by the J-85 rebuild (the create-once path that recomputes forward returns). This is honest
  NA, never a fabricated zero.
- **Max drawdown is always shown as ≤ 0 or NA.** A flat or strictly rising window yields exactly 0.0; a
  window with too few post-snapshot bars yields NA — never a positive "drawdown" and never a fabricated
  fill.
