# Project story so far

Trendora ranks stocks with explainable, evidence-checked signals — this chapter is about making the running app itself trustworthy day to day: fast, honest about its own state, and resilient under heavy background work.

## How it has grown

Early hardening removed a hidden backfill limit, moved slow calculations to run once at ingest instead of live, made restarts near-instant, and added a live status badge. A later round fixed a cluster of low-memory crashes — including a research tool that crashed on every visit — and rewrote the Backtest page's calculation into small running totals with identical output. A further round fixed the site's production start script (it had quietly run slower developer mode), measured every main page loading in well under a tenth of a second, and replaced Regime Lab's blank 90-second spinner with an honest "Still computing" message and Retry button.

A later round proved the app survives a genuine low-memory emergency — a throwaway test starved the backend during its heaviest calculation and it recovered cleanly, no restart needed — and timed the health check under load for the first time. All eight core promises worked at once, though the app still loaded its entire price history into memory during startup housekeeping. The round meant to fix that shipped no code at all — a setup mix-up meant only inspection happened — but it caught, live, that four research pages really do show a blank screen during a slow load, and that a heavy background job pushes memory to its safety limit with no room to spare.

The next round built the fix that iteration missed: the Data page's background refresh, which used to load every stock's entire 30-year price history at once, now works through the stock list in small batches, cutting peak memory 71% with identical numbers, proven byte-for-byte. All four remaining research pages gained the same honest "Still computing" message and Retry button Regime Lab already had, so no research page leaves users staring at a blank screen. The promise that heavy background work never takes the service down was still only partly proven at that point — the automated check couldn't run because the test backend was denied a restart, so a person checked by hand and found it healthy.

This latest round closed the one remaining code gap behind that promise: importing several days of price history in one request now loads the price-history table from disk only once instead of twice, making big data updates faster and lighter on memory, proven not to change any number shown anywhere. The team also finally ran a real, live 70-second stress test of the heaviest background calculation — the health check answered correctly on every single poll throughout, and for the first time the app's exact memory headroom (57% to spare) was written down. An independent double-check caught and fixed, in the same round, a subtle way the new memory-sharing trick could have quietly held onto over a gigabyte of memory forever after a rare failure — nothing shipped broken. What's still missing is proof that the memory savings hold up under a real, heavy import rather than an empty test job; that measurement is next.

## What it can do today

The product lets users browse stock rankings, sector and theme views, backtests, and all five research tools (Regime Lab, Factor Lab, Market Phase & Severity Lab, Regime x Phase x Factor, Severity-velocity). An operator can back-fill any historical range with an honest zero-work explanation, and the status badge stays truthful through startup, updates, or a crash. Heavy calculations are prepared in advance, restarts serve stored numbers immediately, the Backtest page always serves saved results, every research page shows an honest "still working" message instead of a blank screen during a slow load, and multi-day data imports now load the price history from disk only once instead of twice. Proving that heavy background work never takes the whole service down under a real, heavy import is the top priority next.
