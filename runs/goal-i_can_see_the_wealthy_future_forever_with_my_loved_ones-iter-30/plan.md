## What to Build

Backend (all in `app/engine/market_phase.py` unless noted — same single engine, no second computing module):
- **J-89 causal timeline series:** a read-only derivation returning, for resolved as-of D, the per-snapshot-date `{date, phase, p_bear}` series — the SAME per-date FILTERED values `_filtered_bear_path` + `_phase_for` already produce (timeline and panel read ONE derived series). Clamp to dates ≤ D for the clamped consumer.
- **J-89 causal downtrend episodes:** deterministic grouping of the ≤ D phase / P(bear) into maximal Bear/Correction (or P(bear) ≥ new config `downtrend_pbear_threshold`) runs; each episode = `{first_trigger_date, severity_at_trigger, open|closed}`, observed on its dates only. Empty/early history → honest empty list.
- **J-89 FENCED retrospective:** a NEW backward smoother pass over the SAME `config.regime_switching` params → per-date SMOOTHED P(bear), plus a peak-to-trough (Bry-Boschan/NBER-style) "true bear dating" over index closes. Served ONLY behind a separate explicitly-named field/endpoint (`retrospective`); NEVER consumed by `compute_market_phase`, the panel value, episodes, J-90's signal, or any study conditioning. Bry-Boschan min-phase-length / drawdown-amplitude cutoffs MUST be NEW config keys (no literal).
- **J-89 serving:** causal timeline + episodes additive on the SAME `GET /api/market-phase` cached payload; retrospective behind a separate named field (structural fence). Reuse the SAME `_dataset_version` cache key (J-72) and the existing `MarketPhaseCache` — no second cache mechanism, no new table.
- **J-90 causal recovery-turn signal:** config-defined downtrend-exit for D from data ≤ D (phase leaves Bear/Correction OR filtered P(bear) crosses below new config `recovery_signal_pbear_exit` while index reclaims a trailing MA whose window is a new config key). Surface `{is_recovery_turn, reason}` additively on `GET /api/market-phase` — explainable, never a bare flag.
- **J-90 Recovery-Turn Edge study:** NEW read-only study (`research:compute_recovery_turn_edge`, or a dedicated module in `CALC_FILES`) reading the stored append-only `forward_returns` VERBATIM (realized return + MAE/MFE + `max_drawdown`) via the SAME observation-builder discipline `compute_event_study` uses, joined to `scanner_results`/`scanner_runs`, each obs tagged with the CAUSAL as-of phase/severity/P(bear) at the signal date (read from the read-only market-phase derivation, ≤ D, never recomputed). Reports per `config.walk_forward.horizons` the forward-return distribution (mean/median/%-positive/expectancy + downside-only risk-adjusted + aggregate max-drawdown). Honors `view` Episodes⇄Pooled (J-63) and `as_of` All-history⇄As-of (J-32). Low-sample → NA + n (min from config). Recomputes nothing.
- **J-90 serving:** NEW `GET /api/research/recovery-turn-edge` (`horizon`/`view`/`as_of` mirroring `/api/research/event-study`); cache via the existing `event_study_cache` / dataset-version pattern (no new table).
- **J-90 samples drill-down:** new `kind` (`recovery-turn`) in `app/engine/samples.py` `compute_samples` (mirroring `_regime_setup_pattern_samples`) reproducing the recovery-turn cohort from the SAME shared-membership observation builder, so each `N=` chip drills via the EXISTING `GET /api/research/samples` and `total` EQUALS published `n` in BOTH Episodes/Pooled AND All-history/As-of. Add to `ALL_KINDS`; wire validation in `api/research.py` `research_samples` so every displayable row resolves without a 4xx (J-82 lesson).
- **Config:** add NEW typed/validated keys under the EXISTING `market_phase` block in `config.yaml` + `MarketPhaseCfg` (`downtrend_pbear_threshold`; `recovery_signal_pbear_exit`; recovery trailing-MA reclaim window; Bry-Boschan min-phase-length + drawdown-amplitude cutoffs). Validate (in-range / positive); reject malformed at load. NO new top-level section.
