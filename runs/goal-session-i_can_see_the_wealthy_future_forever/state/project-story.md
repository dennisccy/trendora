# Project story so far

Trendora is a local-first, research-only US equity leadership scanner — a decision-support workstation that ranks the market after the close and earns the user's trust with forward-tested evidence rather than ever shouting "buy."

## How it has grown

Trendora arrived already substantially built — a dark dashboard ranking US stocks, sectors, and themes after the close, every score explained and every idea showing what would prove it wrong. Early passes closed the original gaps — one shared date control, click-through from any forward-tested return to the names behind it, a Data Manager that backfills without inventing numbers, matching scores across pages, a restart-proof watchlist, and fast snapshot loads — finishing all nineteen original journeys.

The owner then asked for more: a bigger universe, extra chart timeframes, and research labs. Charts learned to keep drawing past a chosen date to today while scores still reflected only what was known then. Widening the universe toward ~500 names stalled when the one-time download of real price history kept hitting an outage of the free data source — and the team refused to fake it — so work turned to data already in hand: three new chart patterns, then a Research area (a Factor Lab later split by market mood, blended across signals, and extended to a volatility family; a Setup & Pattern Lab studying every past occurrence; and a synthesis capstone linking any finding to the filtered leaderboard and on to a stock's scorecard). A re-scope made the data-blocked items non-halting and gave Research its own all-history ⟷ as-of-date switch.

Then the owner returned with wishes about bringing in real market data: pick which source to import from (pasting a key only when one is needed, and never saving it), run an import that survives a busy source by pausing and resuming, and grow the stock universe straight from the Data Manager. Iteration 21 built the import source picker — choose among Yahoo, Tiingo, Finnhub, Alpha Vantage, and Stooq, see which are ready at a glance, paste a key for one run only — but left one safety gap: a pasted key could still slip into the job's error messages when a provider rejected it.

Iteration 22 closed that gap and went further. The key is now scrubbed out at the point the error is built — the job card, the error list, the run history, and every API response are confirmed clean. At the same time, data imports learned to run in visible batches: the job card now shows "chunk 1 of 7" and advances as chunks complete. When a provider rate-limits the import, the job stops cleanly in an amber "rate-limited — resumable" state — never a red failure — saves its progress to the database, and waits. Clicking Resume picks up from the next un-fetched chunk, skipping anything already saved, and the resumable import survives a full backend restart: the "Resumable imports" panel reappears from the database as soon as the server comes back up.

## What it can do today

The product lets users see the day's market at a glance; browse ranked stocks, sectors, and themes and filter by sector, setup, or chart pattern; open any stock for a plain-English scorecard identical on the list and the detail page; rewind the whole app to any past day with one shared date control; read forward-tested evidence by score grade, benchmark, and control group on the Backtest page; explore the Research area to test whether a signal sorts future returns — by factor decile, by market mood, as a multi-signal blend, and across a volatility family, each viewable all-history or rewound to a point in time; study any setup or pattern's full track record; travel from a finding to the names behind it and on to the scorecard; keep a restart-proof watchlist; grow the dataset by date; look up every label in a plain-language glossary — always with honest "not enough data yet" marks; choose which data provider to import from with a pasted key held for that run only; and start a large import that runs in visible chunks, pauses gracefully on a rate limit, and can be resumed even after restarting the server.
