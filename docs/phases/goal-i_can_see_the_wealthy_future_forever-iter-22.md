### Root cause of the leak (code-verified)

- `apps/backend/app/data_providers/_http.py` — the old `except httpx.HTTPError as exc: raise ProviderUnavailableError(f"{label} request failed for {symbol!r}: {exc}")`. For a non-2xx response `response.raise_for_status()` raises `httpx.HTTPStatusError`, and `str(exc)` embeds the **full request URL including the query string**.
- The keys travel as **URL query params**: `tiingo_provider.py:46` `params={"token": self._api_key, ...}`, `finnhub_provider.py:53` `"token": self._api_key`, `alpha_vantage_provider.py:51` `"apikey": self._api_key`. So the rendered `str(exc)` contains `?token=<KEY>` / `?apikey=<KEY>`.
- Flow to the UI: `_http.py` → `data_manager._do_fetch _record_error` → `JobProgress.errors` → `to_dict()` → `GET /api/data/jobs/{id}` → the `/data` job-card error list (`page.tsx`).
- **Why the 502-green suite missed it (the blind spot):** `tests/test_provider_clients.py` `_FakeResponse.raise_for_status()` raises `httpx.HTTPStatusError("HTTP {code}", request=httpx.Request("GET", "http://x"), response=None)` — a hard-coded `http://x` request URL with **no key**, so `str(exc)` is just `"HTTP 429"`. The real client path (a real `Response.raise_for_status()` whose `.request.url` carries the params) is never exercised. `tests/test_data_manager.py test_pasted_api_key_never_persisted` injects a *mocked* provider raising a *sanitized* error — same blind spot.

- [ ] **Chunked fetch engine (`apps/backend/app/engine/data_manager.py`).** Replace the single-shot `_do_fetch` symbol loop with a **batched** loop that is the one fetch path (J-17's small jobs become a single chunk):
  - Build a deterministic chunk plan = (symbol-batches of `symbol_batch_size` over the stable `all_seed_symbols(cfg)` ordering) × (date-windows of `date_window_days` over `[start, end]`). Record `chunk_total` and the symbol plan on the checkpoint at job start.
  - For each chunk from `next_chunk_index`: fetch its symbols (reusing the existing `_existing_dates` INSERT-**new-only** guard → per-`(symbol, date)` idempotency, never overwriting a committed bar). Sleep `inter_request_sleep_seconds` between requests (the sleep function MUST be injectable / config-zeroed so tests stay fast — see Testing). Update live `JobProgress` (new `chunk_index`/`chunk_total` fields) AND persist the checkpoint **after each completed chunk** (`next_chunk_index += 1`, counters, `updated_at`).
  - On `RateLimitError`: retry the **current** chunk with exponential backoff up to `max_retries`; if the limit still persists, **stop gracefully** — set `JobProgress.status` and the checkpoint `status` to `resumable` (distinct from `failed`), record symbols done vs remaining, persist, and return. **Fabricate nothing; do not raise; do not halt the loop.**

- [ ] **Resume path (`apps/backend/app/engine/data_manager.py` + `apps/backend/app/api/data.py`).** Add `resume_data_job(import_id, *, api_key=None, ...)`: load the persisted `ImportCheckpoint`, register a fresh in-memory `JobProgress` seeded from it (same `import_id`), and run the chunk loop **from `next_chunk_index`** — re-fetching nothing already stored.
